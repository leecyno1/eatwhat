# 吃什么 App 重设计方案（V2）

目标：以“气泡滑动偏好学习”为核心，构建可上线的 iOS 优先版本，解决用户选择困难，形成“偏好 → 候选美食 → 菜谱/外卖/附近餐馆”的闭环体验。

## 1. 用户旅程（Happy Path）
1) 首启引导：选择饮食限制（素食/过敏）、口味偏好（辣/酸/甜…）、预算、时间、心情（清淡/解压/冒险）。
2) 气泡滑动：上滑喜欢、下滑不喜欢；支持撤销、长按查看示例菜、轻触调节权重。
3) 生成候选：5–9 个多样性菜品卡片，含图、口味标签、时长、价格区间、热量估算。
4) 选择结果：
   - 做饭：给菜谱（步骤、用料、替代方案、器具），可加购清单。
   - 外卖：深链至美团/饿了么（或 H5），或打开“附近餐馆”（Apple 地图/高德）。
5) 反馈闭环：吃完后 1–2 问题轻评价，更新偏好与探索度。

## 2. MVP 范围
- 必做：气泡偏好学习、候选生成、菜谱、外链打开、附近搜索、离线食谱库（FTS）。
- 可选：心情模型、卡路里/营养估算、A/B 探索策略、账号云同步。

## 3. 技术蓝图（概览）
- 状态管理：Provider → 渐进迁移 Riverpod（从偏好引擎开始）。
- 数据：本地 SQLite（FTS5）+ Hive（会话/配置）；食谱来自内置 DB（howtocook/下厨房处理后）。
- 推荐：内容画像（口味/食材/烹饪法）× 线上成对偏好学习（BT/Logistic），并行加入探索（ε-greedy）。
- 外部：`url_launcher` 打开外卖深链/网页；Apple 地图本地搜索；Sentry 监控 + Analytics。

## 4. 里程碑
- M0（本周）：偏好引擎原型、候选生成器、离线检索、气泡交互强化；单测覆盖核心算法。
- M1（+1 周）：心情/上下文（时间/天气/位置）加权，多样性优化，iOS TestFlight。
- M2（+2–3 周）：餐馆联动、外卖深链回退策略、埋点与增长指标、性能调优。

## 5. 风险与对策
- 冷启动：首启问卷 + 探索采样；
- 数据质量：统一菜品/口味/标签本体库与同义词；
- 合规：外卖为实物交易，使用外链/SFSafariViewController；隐私合规与定位权限文案完善。
