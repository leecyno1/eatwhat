## 一、正确入口

**优先入口：[外卖通用解决方案](https://open.waimai.meituan.com/program/general) → [创建应用/管理平台](https://open.waimai.meituan.com/manage/basic)。**

同一次内嵌浏览器会话已成功进入外卖管理平台，不需要另建浏览器 profile。用户补充基础资料后已创建「吃什么」应用，但尚未通过接口上线所需资质认证。

接口权限页提示「您尚未进行资质认证，认证后才可以申请上线，资质暂只支持填写一次」。点击「去认证」，再进入[外卖通用解决方案开发者申请入口](https://developer.meituan.com/isv/register)，可以选择目标业务。

当前认证表单要求：

- 合作业务、可接入门店数、门店订单量、接口调用量、合作年限、主营业务和经营区域，须按实际情况填写。
- 申请人姓名、手机号、邮箱、证件号、手持证件图片。
- 营业执照信息及图片、法人姓名/手机号/证件号与正反面图片；三证合一无需另传组织机构代码证。
- 电子合同签约人、公司简介；官方网站为非必填项。
- WAF 安全产品情况、安全证明、信息安全人员情况、加盖企业公章的数据交互合规化承诺书。

安全证明是必填项；本次选择外卖通用方案后，等保证明选项可选，而网络安全保险选项为禁用状态。禁用原因及是否有其它合规替代方式尚未确认，不能自行启用控件或直接推荐购买保险。

页面流程为「资质认证 → 签署电子合同 → 缴纳保证金 → 入驻成功」，并注明保证金额度根据企业资质判定，未展示具体金额。尚未提交认证、签约或支付费用。

## 二、产品能力与边界

目标产品是「外卖通用解决方案」，不是商家 ERP 接单、连锁门店管理或配送发单。

[综合能力页](https://developer.meituan.com/isv/waimai)明确列出适合「第三方APP」。官方文档列有：

- 商家列表、商家详情、菜品列表、搜索建议。
- 购物车价格计算、订单预览、提交订单、订单列表/详情、取消订单。
- 预计送达时间、用户地址查询及新增/更新。

这些是**文档化能力**；当前账号尚未完成权限申请与真实调用验收。

消费者本人完成 OAuth 授权后才可调用相应用户接口，不是让消费者注册商家。
OpenH5/SDK 是平台提供的页面或组件接入方式；不能与 App 自建界面通过 API 提交订单混为一谈。

[提交订单文档](https://developer.meituan.com/docs/biz/biz_wmh5api_33922ecb-0ed8-4ab9-8894-6e46dd244e5d)明确提供 `POST /openapi/v1/order/submit`，返回订单号与 `payUrl`，随后跳转美团收银台完成支付。因此是 API 创建订单加平台收银台支付，不是无感扣款。
该旧文档还列有未审核时仅可使用指定商家参数的限制；测试商家当前是否仍有效，须平台确认，不能随意在真实门店发测试订单。

## 四、应用与服务端配置

[OAuth 文档](https://developer.meituan.com/docs/biz/biz_wmh5api_da85b8ae-b59b-4c72-815a-af7048706db0)（更新于 2024-01-30）要求：
「注册开发者帐号，并拥有一个已审核通过的网站应用，获得相应的 AppID 和 AppSecret」。

取得获批凭据后，在服务端配置，不能打包到 Flutter 客户端：

```dotenv
MEITUAN_OPEN_APP_ID=<获批应用的 app_id>
MEITUAN_OPEN_APP_SECRET=<获批应用的 app_secret>
MEITUAN_OAUTH_REDIRECT_URL=https://<实际公网域名>/oauth/callback
MEITUAN_OAUTH_SCOPE=
MEITUAN_OPEN_ORDER_ENABLED=false
```

回调由 `scripts/meituan_delivery_adapter_server.dart` 提供，生产应使用 HTTPS，经网关转发。
订单开关在获得相应权限、确认测试商家/支付方式后再开启；构建成功不代表真实下单已验收。

## 五、OAuth scope 与端点

官方参数表：`scope | 是 | 应用授权作用域,填"" 即可`。默认保持空字符串。
此前在授权预览返回 10005 时观察到的白屏，不能据此推断必须使用 `all`，也不能排除其它因素。

| 端点 | 用途 | 当前源码情况 |
|---|---|---|
| `/oauth/authorize` | 获取授权 code | 已引用 |
| `/oauth/access_token` | code 换 token | 已引用 |
| `/oauth/refresh_token` | 续期 | 已引用 |
| `/oauth/userinfo` | access_token 取用户信息 | 已引用 |
| `/oauth/userinfo_openid` | open_id 取用户信息 | 文档有列出，当前服务未实现 |

上述源码情况核验于 `scripts/meituan_oauth_service.dart`，不等于已获平台联调通过。
`refresh_token` 失效后需重新授权；state 一次性使用，当前代码有效期 30 分钟。

## 六、业务签名与密钥安全

[快速接入](https://developer.meituan.com/docs/biz/biz_wmh5api_4bd84411-fbc1-4668-b1e6-8c5cf255b1f4)要求：

1. 除 `sign` 外的认证参数和业务参数按参数名排序，用 `&` 连接。
2. 拼接 `请求url + "?" + 排序参数 + secret_sign`。
3. MD5 结果作为 `sign`。

认证参数包含 Unix 秒级 `timestamp`、`app_id`、`access_token` 或 `open_id`。
坐标文档口径为火星坐标系乘以 1000000。
仓库已有 `MeituanOpenApiSigner`；实际请求参数、支付与回调仍须联调。

官方要求 secret 和用户 token 保存在 App 云端服务器，由服务端中转调用。
不要把 AppSecret、access_token、refresh_token 写入客户端、仓库、日志或截图。

## 七、开通后的验收

1. 代理 `/health` 可达，确认配置状态；健康检查不证明平台权限有效。
2. 完成一次消费者 OAuth，检查 `/api/v1/delivery/oauth/status`。
3. 使用真实位置查询门店与菜单，验证购物车价格及订单预览。
4. 在平台允许的测试方式下，验证订单提交、支付、状态及回调；真实付费订单需用户确认。
5. 再验证 App 的正常路径、失败提示与离页生命周期。

未完成这些步骤前，不得写“代码侧全部就绪、只等密钥”。是否接受暂不提供外卖的版本，由用户决定。

## 八、综合门户调查的适用范围

综合门户 `/isv/newRegister` 的提示弹层关闭后，可以正常展开对接类型。
本次列表包含到店餐饮、服务零售、酒旅民宿，以及数据分析、集成平台、手机厂商等类型，未见明确的「外卖通用方案」。
这仅说明该表单未明确列出目标产品，**不能据此排除独立外卖平台的自助创建路径**。后续从独立平台认证页进入的 `/isv/register` 是另一份表单，明确列有外卖通用方案，并要求企业认证。

品牌商通道面向连锁品牌；个人开发者读到的一份指南为酒旅 Skills。未穷尽其它能力，不推断用户缺少商标/门店，也不据此断言个人永远无法接入外卖。
