# 首启手感教学与气泡发放去重设计

- 日期：2026-10-31
- 状态：已确认（2026-10-31）
- 范围：首启教学动画、气泡重复发放修复
- 非目标：不改核心容器布局、物理参数、视觉皮肤、气泡尺寸、页头与底部控制栏

## 1. 背景

当前首次打开会出现两套独立引导：

1. `OnboardingOverlay` 在 AppV2 启动后插入根 Overlay，显示四步教学。
2. `HomeFirstUseGuideCard` 在 HomePage 首帧后用 `showGeneralDialog` 再显示一次说明。

四步教学的内容与真实交互不一致：它教“长按收藏、上滑喜欢、下滑不喜欢”，实际核心容器是“点选收下、按住拖到顶部收下/底部拉黑、摇一摇翻锅”。

用户同时反馈核心容器里出现重复卡片。静态数据没有重复：94 个标签 ID 与 94 张实体图一一对应，牌组生成也按 label 去重。重复来自运行时发放。

## 2. 重复发放根因

`BubbleGame._addBubbles` 当前从 `world.children` 推导已存在的气泡 ID。Flame 1.34 的 `add` 会先入队，`BubbleBody.onLoad` 还要异步读取图片轮廓；在实体真正挂载前，它不在 `world.children` 中。

因此：

- 开场第一波、0.5 秒后的第二波、0.28 秒补充流可能互相看不到对方已发放的 ID。
- 分类切换时，排队中的实体也无法通过遍历 `world.children` 清除。
- 同一标签 ID 可以出现两个实体，视觉上就是重复卡片。

现有测试只覆盖 `BubbleDataManager` 的单次输出，没有实例化 `BubbleGame`，所以测不到该缺陷。

## 3. 重复发放修复设计

### 3.1 核心改动

`BubbleGame` 自己维护发放台账，而不是从已挂载子树反推：

- 新增内部集合 `_issuedTagIds`，在调用 `world.add` 前立即写入当前标签 ID。
- `_dataManager.getInitialBubbles` 的排除集合始终包含 `_issuedTagIds + selectedTagIds + blockedTagIds`。
- 同一 tick 只允许一个投放批次；补充流在投放批次完成登记后才会继续。
- 标签池耗尽时宁可少显示实体，不重复发放。
- 选择或拉黑后的 ID 继续保留在台账中，不重新投放。

### 3.2 分类切换与重载

- 新增 `_spawnGeneration` 代次号。每次 `_reloadBubbles` 自增。
- 清理时同时处理已挂载实体和排队中的 `BubbleBody`。
- 排队实体完成挂载时检查代次；代次过期则立即自我移除，不能污染新分类。
- 重载时清空旧代次台账，只保留当前选择与拉黑集合作为排除项。

该修复不改变容器视觉、物理参数和手势行为。

### 3.3 测试

新增两个层次的回归：

1. 纯 Dart 台账测试：重复 reserve 同一 ID 只成功一次；重载后旧代次失效；标签耗尽不重复。
2. 游戏生命周期测试：注入可控延迟的轮廓加载器，在实体尚未挂载时推进 0.3 秒与 0.5 秒，断言所有实体 ID 唯一；再快速切换分类，断言旧代次实体不会残留。

验收标准：

- 首屏展开期间所有存活实体 ID 唯一。
- 连续选择、拉黑、补充 15 秒后 ID 仍唯一。
- 分类切换后不出现旧分类实体，也不出现同 ID 双份。
- 核心容器的视觉和操作手感无可感知变化。

## 4. 首启教学动画设计

### 4.1 统一入口

- 删除 HomePage 的 `_showFirstUseGuideIfNeeded` 与 `HomeFirstUseGuideCard` 入口。
- AppV2 不再主动插入旧 OnboardingOverlay。
- 首启教学只由 HomePage 在首帧后检查一个版本化标记并显示。
- 新标记：`handfeel_tutorial_v1_seen`。
- 为兼容已有安装与既有测试，旧标记 `has_seen_onboarding_v2` 或 `v2_home_generation_guide_seen` 任一为 true 时，也视为已看过。
- 用户完成或跳过时写入标记；中途被杀进程则下次重新出现。
- 本轮不增加回看入口，避免扩大页头范围。

### 4.2 教学结构

唯一教学名为“开席三式”，只教真实动作：

1. 轻点：点一下气泡收下偏好。
2. 按住拖动：往上进顶部收下区，往下进底部拉黑区。
3. 摇一摇：晃动手机让锅里的实体重新翻动。

不再教收藏手势，不再教不存在的上下滑喜欢/不喜欢。

### 4.3 画面与连续性

- 教学层覆盖首页主体，但真实气泡舞台仍以低亮度可见；使用渐变压暗与金色暗角，不使用昂贵的大面积 BackdropFilter。
- 中央是一个与真实舞台同语汇的迷你舞台，使用现有 `preference_entities` 食材图，不新建图片资产。
- 三步共用同一张主卡和同一空间，不做三张互不相关的页面：
  - 第一步：主卡被指尖轻点，金线涟漪扩散，主卡轻微压缩后回弹。
  - 第二步：同一张主卡被按住抬起，沿曲线移到顶部叶绿收下区，再落回并下沉到底部红色拉黑区。
  - 第三步：迷你舞台整体做阻尼晃动，实体小幅翻动，金色微粒只出现一次。
- 顶部文案为衬线标题，底部是紧凑说明与“下一步/开始挑第一口”。右上角常驻“跳过”。
- 视觉语言沿用黑金、米白、叶绿、番茄红；使用已有字体与 token。

### 4.4 动效参数

- 入场：520ms，幕布淡入、标题上浮 16px、迷你舞台从 0.96 缩放到 1。
- 步骤切换：280ms，共享主卡连续移动，文案 160ms 交叉淡出淡入。
- 点按演示：一次 700ms 压缩回弹，不做无限快闪循环。
- 拖拽演示：单次 1.8s 弧线路径，顶部与底部投放区各点亮一次。
- 摇晃演示：单次 2.0s 阻尼摆动，结束后静止等待用户继续。
- 完成：360ms 淡出并交还真实舞台。
- 每一步进入时触发一次轻触觉反馈，不连续震动。
- `MediaQuery.disableAnimations` 或系统减少动态效果开启时：取消循环与位移动画，只保留静态分镜和即时切换。

### 4.5 交互与可访问性

- 点击主按钮或教学内容区域可推进，右上角跳过随时可用。
- 教学层吸收触摸，不能让点击穿透到真实舞台。
- “跳过”和“下一步”触控高度不小于 48dp。
- 每个步骤提供 Semantics 标题与说明，进度使用可读文本，不仅依赖颜色。
- 文本缩放至 1.3 倍时不溢出；窄屏 320px 下主按钮与说明保持可见。

## 5. 触发与状态

- HomePage 在首帧后读取 `handfeel_tutorial_v1_seen`。
- 教学显示前确保 HomePage 已退出初始加载态；若气泡舞台仍在加载，允许已有舞台先呈现一帧再覆盖，不使用固定延时猜测。
- 教学完成后写入标记并移除教学层；再次启动不再显示。
- 测试环境通过 SharedPreferences mock 保持既有主链路不弹教学。
- 不新增远程配置、不上报教学内容点击，保持本地隐私承诺。

## 6. 测试与验收

### 自动化

- 首启测试：首次进入显示三步；点“下一步”按 tap → drag → shake 顺序推进；完成写入新标记。
- 跳过测试：跳过立即关闭并写入标记。
- 第二次启动测试：标记为 true 时不出现教学，也不出现旧首页说明卡。
- 动画测试：禁用动画时步骤仍可完成，无定时器泄漏。
- 窄屏与文字缩放测试：320px、1.3 倍字号无溢出。
- 回归：现有首页、推荐、结果页、引导相关测试全部通过。

### 模拟器验收

1. 清空 App 数据，启动后看到唯一的开席三式。
2. 点按、拖拽、摇晃三章动画连续，切换无跳帧或布局抖动。
3. 跳过与完成后都不再出现旧四步遮罩或首页说明卡。
4. 连续观察核心容器 15 秒，不出现同图重复；分类切换不残留旧实体。
5. 真实舞台的点选、抓取、顶部收下、底部拉黑、摇一摇保持原状。

## 7. 风险与回滚

- Flame 排队组件清理复杂，必须用代次号与生命周期测试保护；若实现不稳定，保留内部发放台账修复，暂缓分类切换的彻底清理，但不得回退到从 `world.children` 去重。
- 教学动画若造成低端机掉帧，移除粒子与暗角，不移除三段教学本身。
- 全部改动不涉及数据库、服务端、支付、外卖与账号。

## 8. 完成标准

- 首启只有一套准确的教学，动画连续且可跳过。
- 核心容器不出现重复卡片，视觉与手感保持原样。
- 新增回归测试能在旧实现上复现重复发放，在新实现上通过。
- `dart format`、`flutter analyze`、`flutter test` 全绿。
