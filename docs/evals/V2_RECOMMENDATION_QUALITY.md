# V2 推荐质量离线评测

基线日期：2026-08-04  
算法版本：`hybrid_v3_0`  
数据基线：`assets/data/unified_recipes.db`

## 目标

这套评测把推荐链路的关键产品承诺变成可重复执行的代码门槛：正式结果必须来自本地统一菜谱库，忌口与过敏约束不能穿透，同时维持候选覆盖、多样性、稳定性和可接受延迟。

## Capability evals

1. 默认家常场景能返回不少于 3 道正式候选。
2. 快手、清淡和暖胃偏好能返回与需求有文本或标签关联的候选。
3. 海鲜过敏、素食、清真和不要辣场景中，禁止词不能出现在最终菜名、描述、食材或标签中。
4. 所有最终结果都具有可解析的本地 `dishId`，且不存在重复或占位菜谱。
5. 每个场景的推荐多样性分数不低于场景门槛。

## Regression evals

1. `primarySource` 保持为 `unified_db`，算法版本保持为 `hybrid_v3_0`。
2. 8 个固定场景的 pass@1 必须为 100%。
3. 海鲜过敏、素食、不要辣三个关键场景必须达到 pass^3 = 100%，且三次结果顺序一致。
4. 硬约束通过率、正式身份通过率和候选覆盖率必须为 100%。
5. 全场景平均多样性不低于 0.55，P95 推荐延迟低于 3 秒。

## 评分方式

- 代码评分器：身份、数量、重复、占位数据、禁止词、约束标签、相关词、多样性和延迟。
- 不使用模型评分器，避免网络、模型版本和随机性导致 CI 波动。
- 预算和人数目前仅参与排序，`RecipeModel` 尚未暴露成本与份量字段，因此本阶段不把它们作为独立硬约束评分项。

## 固定场景

| ID | 场景 | 主要门槛 |
| --- | --- | --- |
| `default_home` | 默认家常热菜 | 覆盖、多样性、正式身份 |
| `quick_meal` | 15 分钟快手菜 | 快手相关性、时间约束已应用 |
| `light_meal` | 清淡少油 | 清淡相关性 |
| `warm_comfort` | 热乎暖胃 | 热菜、汤羹或主食相关性 |
| `seafood_allergy` | 海鲜过敏 | 水产词零穿透，pass^3 |
| `vegetarian` | 素食 | 肉类词零穿透，pass^3 |
| `halal` | 清真、不吃猪肉 | 猪肉相关词零穿透 |
| `no_spicy` | 不要辣 | 辣味词零穿透，pass^3 |

## 执行

```bash
flutter test test/recommendation/v2_recommendation_eval_test.dart
```
